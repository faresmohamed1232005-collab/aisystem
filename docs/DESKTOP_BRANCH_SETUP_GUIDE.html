دليل إعداد وربط تطبيق الصيدلية المكتبي

شرح بيانات شاشة أول تشغيل والمسؤول عن تجهيز كل قيمة

تظهر شاشة «إعداد الفرع» مرة واحدة عند تشغيل التطبيق على جهاز جديد. وظيفتها ربط الجهاز بفرع محدد وبحساب الصيدلية على السيرفر المركزي، ثم تنزيل البيانات اللازمة للعمل بدون إنترنت.

توزيع المسؤوليات

مسؤول النظام / المبرمجصاحب الصيدلية أو مدير الفرع
تجهيز السيرفر والدومين، إنشاء مفتاح المزامنة، تشغيل migrations، اعتماد حساب المالك، وتحديد أكواد الفروع. إدخال كود واسم الفرع وبيانات حساب المالك التي يستخدمها في نسخة الويب.

شرح خانات شاشة الإعداد

1) كود الفرع

يحدده مسؤول النظام / صاحب الصيدلية

رمز فريد لكل فرع، ويُستخدم كبادئة لأرقام الفواتير.

أمثلة: MAIN للفرع الرئيسي، MAADI للمعادي، NASR لمدينة نصر.

مهم: لا تستخدم نفس الكود لفرعين مختلفين.

2) اسم الفرع

صاحب الصيدلية / مدير الفرع

اسم واضح يظهر في التقارير وإدارة التحويلات، مثل: الفرع الرئيسي أو فرع المعادي. الخانة اختيارية لكن يُفضّل تعبئتها.

3) رابط السيرفر المركزي

يوفره المبرمج

رابط نسخة الويب المنشورة Online، بدون شرطة مائلة في النهاية.

مثال إنتاجي: https://pharmacy.example.com

للتجربة على نفس جهاز التطوير فقط: http://pharmacy_sys.test

الرابط المحلي لا يعمل من جهاز عميل آخر؛ يجب وقتها استخدام دومين أو IP يمكن الوصول إليه.

4) مفتاح المزامنة (SYNC_TOKEN)

ينشئه ويحفظه المبرمج

سر مشترك بين السيرفر وتطبيقات الفروع. ليس كلمة مرور المالك ولا كلمة مرور قاعدة البيانات.

يُنشأ مرة بقيمة قوية، ثم تُوضع نفس القيمة في إعدادات السيرفر وفي شاشة إعداد الفرع.

مثال توليد على السيرفر: php artisan tinker --execute="echo bin2hex(random_bytes(32));"

سري: لا ترسل قيمة Token في ملف الدليل، ولا تنشرها في صور أو محادثات عامة. اكتب مكانها دائمًا [يُسلّم بشكل آمن].

5) بريد أو اسم مستخدم الصيدلية

صاحب حساب الصيدلية

هو نفس البريد أو اسم المستخدم الذي يسجل به مالك الصيدلية الدخول إلى نسخة الويب. يجب أن يكون الحساب موجودًا ومفعّلًا على السيرفر.

6) كلمة مرور الصيدلية

صاحب حساب الصيدلية

كلمة مرور حساب المالك على نسخة الويب. تُستخدم للتحقق وربط الفرع بالحساب، وليست مفتاح المزامنة.

إعدادات السيرفر المطلوبة — للمبرمج

في ملف البيئة الخاص بالسيرفر المركزي:

SYNC_ENABLED=true
SYNC_TOKEN=[قيمة سرية قوية]
BRANCH_ID=server
SERVER_BRANCH_ID=server

بعد التعديل:

php artisan migrate --force
php artisan optimize:clear

قائمة مراجعة قبل الضغط على «تسجيل الفرع»

  • السيرفر المركزي يعمل ويمكن فتح رابطه من جهاز الفرع.
  • تم تشغيل migrations على السيرفر.
  • تم ضبط SYNC_TOKEN على السيرفر.
  • كود الفرع فريد وغير مستخدم لصيدلية أخرى.
  • حساب المالك موجود ومعتمد وكلمة مروره صحيحة.
  • الإنترنت متاح أثناء التسجيل والمزامنة الأولى.

ماذا يحدث بعد التسجيل؟

  1. يتحقق السيرفر من Token ومن بيانات حساب المالك.
  2. ينشئ أو يربط الفرع ويعيد هوية ثابتة للجهاز.
  3. يحفظ التطبيق بيانات الربط محليًا.
  4. تبدأ أول مزامنة لتنزيل حساب الصيدلية والموظفين والكتالوج.
  5. بعد اكتمال التنزيل يستطيع التطبيق العمل Offline.
اقتراح للإنتاج: الأفضل مستقبلًا استبدال رابط السيرفر وSYNC_TOKEN بكود تفعيل واحد يصدره الأدمن، حتى تكون شاشة العميل أبسط وأكثر أمانًا.

إنشاء نسخة Windows من GitHub Actions

  1. افتح مستودع المشروع على GitHub، ثم اختر Actions.
  2. اختر Workflow باسم Build Desktop Windows.
  3. اضغط Run workflow، واختر فرع main، ثم ابدأ التشغيل.
  4. انتظر نجاح خطوات الاختبارات وBuild Guard وبناء NativePHP.
  5. من أسفل صفحة التشغيل نزّل Artifact الذي يبدأ اسمه بـ pharmacy-desktop-windows-x64-.
  6. فك الملف المضغوط، ثم تحقق من SHA-256 بمقارنة ملف SHA256SUMS.txt مع الأمر Get-FileHash .\اسم-الملف-setup.exe -Algorithm SHA256.
  7. جرّب ملف *-setup.exe أولًا داخل Windows Sandbox أو VM أو جهاز اختبار لا يحتوي بيانات عمل.
الـBuild يتم على جهاز Windows مؤقت تابع لـGitHub باستخدام SQLite معزولة، ولا يصل إلى Laragon أو MySQL أو ملفات AppData على أجهزة العمل. قد يظهر تحذير Windows SmartScreen لأن ملف التثبيت التجريبي غير موقّع بشهادة Code Signing.
هذا الملف لا يحتوي أي مفاتيح أو كلمات مرور حقيقية، ويمكن مشاركته أو حفظه بصيغة PDF بأمان.
